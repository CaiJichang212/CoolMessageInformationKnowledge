# superpowers的最佳平替是什么？

推荐的“最佳平替”不是单一工具，而是这套组合：

**GitHub Spec Kit + 原生 Claude Code / Codex Plan Mode + `AGENTS.md` / `CLAUDE.md` + 少量自定义 Skills / Hooks。**

如果必须选一个最接近 Superpowers、但更稳、更轻、更通用的替代品：**首选 GitHub Spec Kit。**

Superpowers 本质上是一个“完整软件开发方法论 + composable skills（可组合技能）”框架，会强制 agent 先澄清需求、写 spec（规格）、写 implementation plan（实施计划）、强调 TDD（测试驱动开发）和小步执行。它的优点是纪律性强，但缺点也明显：流程偏重，计划文档容易膨胀，尤其 `writing-plans` 会把实现代码写得过细。Superpowers 官方 README 也明确说它会让 agent 先产出 spec，再产出一个“enthusiastic junior engineer”也能执行的实施计划，并强调 TDD / YAGNI / DRY。([GitHub][1])

我的排序如下。

| 推荐级别 | 替代方案                                           | 适合场景                                     | 评价                 |
| ---- | ---------------------------------------------- | ---------------------------------------- | ------------------ |
| 第一推荐 | **GitHub Spec Kit**                            | 想替代 Superpowers 的 spec / plan / tasks 流程 | 最均衡                |
| 第二推荐 | **Claude Code 原生 Skills + Hooks + Plan Mode**  | 主要用 Claude Code                          | 最自然、最少额外框架         |
| 第三推荐 | **Codex Plan Mode + `AGENTS.md` + `PLANS.md`** | 主要用 Codex / OpenAI 工具链                   | 轻量、标准化             |
| 第四推荐 | **Agent OS**                                   | 想管理团队编码规范、项目标准                           | 轻量，偏 standards（标准） |
| 第五推荐 | **BMAD Method**                                | 从产品、PRD、架构到实现全流程管理                       | 强大但重，不适合所有项目       |

**我的首选：GitHub Spec Kit。** 它的核心流程是 `Spec → Plan → Tasks → Implement`，也就是先定义要做什么，再制定技术计划，再拆成任务，最后让 coding agent 执行。它和 Superpowers 的目标很接近，但更偏“规范驱动开发”（Spec-Driven Development, SDD），而不是把一堆技能强行塞进 agent 行为里。官方文档强调每个阶段产出 Markdown artifact（文档产物），逐步喂给 agent，避免 ad-hoc prompt（临时提示词）混乱。([GitHub Docs][2]) GitHub 的介绍也明确说，Spec Kit 把任务拆成小的、可评审、可单独测试的 chunks（工作块），而不是让你审查上千行代码 dump（代码倾倒）。([The GitHub Blog][3])

Spec Kit 另一个强点是**不锁定 agent**。官方文档显示它支持 Copilot、Gemini、Codex、Windsurf、Claude、Kiro 等多种集成，并提供 generic integration（通用集成）作为兜底。([GitHub Docs][2]) 这比 Superpowers 更适合长期使用，因为你不会被某一个 CLI、某个技能体系、某个模型供应商绑定。

**如果你主要用 Claude Code：不要再找大型替代框架，直接用原生能力。** Claude Code 现在已经有 Plan Mode（规划模式）、Skills（技能）、Hooks（钩子）、MCP（Model Context Protocol，模型上下文协议）等机制。Anthropic 官方文档建议把项目或团队的可复用领域知识写成 `.claude/skills/.../SKILL.md`，Claude 会在相关任务中自动使用，或者你可以通过 `/skill-name` 显式调用。([Claude Code][4]) Hooks 则适合做“必须每次执行”的确定性动作，比如每次编辑后格式化、阻止危险命令、运行 lint（静态检查）等；官方明确说 hooks 比 `CLAUDE.md` 指令更确定，因为它不是建议，而是自动执行。([Claude Code][4])

Claude Skills 也比 Superpowers 更“正统”。Anthropic 2025 年推出 Agent Skills，并在 2025 年 12 月发布为跨平台 open standard（开放标准）。它的核心设计是 progressive disclosure（渐进式上下文披露）：启动时只加载 skill 的 name / description，真正需要时才读取完整 `SKILL.md`，如果内容更复杂，还可以拆到额外文件中按需读取。([Anthropic][5])([Anthropic][5]) 这正好解决 Superpowers 容易把上下文塞得过满的问题。

**如果你主要用 Codex：用 Codex 原生 Plan Mode + `AGENTS.md` + `PLANS.md`。** OpenAI 官方最佳实践建议复杂、模糊、难描述的任务先进入 Plan Mode，让 Codex 先收集上下文、提问、生成计划，再实现；高级工作流可以用 `PLANS.md` / execution plan template（执行计划模板）。([OpenAI 开发者][6]) 对可复用工程规范，OpenAI 建议写 `AGENTS.md`，包括 repo layout（仓库结构）、build/test/lint 命令、工程约定、PR 期望、约束、done definition（完成定义）和验证方式。([OpenAI 开发者][6])

**Agent OS 适合替代 Superpowers 的“项目规则和编码标准”部分。** 它不是完整 agent 框架，而是一个轻量系统，用来发现、维护和注入 coding standards（编码标准）。官方说它主要补足“每次 prompt 都要重新教 AI 项目上下文和团队规范”的问题，并且是 complement（补充）Claude Code、Cursor 等工具，而不是替代它们。([buildermethods.com][7]) 如果你的痛点是“agent 不遵守项目规范”，Agent OS 比 Superpowers 更聚焦。

**BMAD Method 适合大项目，但我不建议默认替换成它。** BMAD 官方定位是从 ideation（构思）、planning（规划）到 agentic implementation（代理式实现）的完整 AI-driven development framework（AI 驱动开发框架），带 specialized AI agents（专门代理）、guided workflows（引导式流程）和复杂度自适应规划。([BMAD Method][8]) 它还有 PM、Architect、Developer、UX 等 12+ 专家代理角色，覆盖完整生命周期。([GitHub][9]) 这对从 0 到 1 做产品、SaaS、复杂业务系统有价值；但对科研代码、算法实验、已有 repo 的 feature / bugfix，通常太重。

我的最终建议是：

**日常工程：Claude Code / Codex 原生 Plan Mode + `AGENTS.md` / `CLAUDE.md`。**

**中大型功能：GitHub Spec Kit。**

**团队规范沉淀：Agent OS。**

**复杂产品从 0 到 1：BMAD。**

**不建议继续把 Superpowers 当主框架使用，尤其不建议直接使用它默认的 `writing-plans` 风格。**

一个更合理的替代架构是：

```text
repo/
  AGENTS.md 或 CLAUDE.md        # 项目级 agent 规则：命令、约束、验收标准
  specs/
    feature-x/
      spec.md                  # 用户目标、需求、非目标
      plan.md                  # 技术设计、架构、风险
      tasks.md                 # 小任务、验收标准
  .claude/
    skills/
      code-review/SKILL.md     # 代码审查流程
      test-first/SKILL.md      # 测试优先流程
      research-code/SKILL.md   # 科研代码规范
    settings.json              # hooks：lint/test/format/安全限制
```

对于你这种 LLM / Agent / 具身智能研究 + 工程落地场景，我会这样选：

科研原型、实验 repo：**Codex / Claude 原生 Plan Mode + 简洁 `AGENTS.md`**。

多人协作项目：**Spec Kit + `AGENTS.md` + CI hooks**。

长期产品或复杂平台：**Spec Kit + Agent OS**。

真的需要 PM/架构师/测试专家多角色工作流时，再上 **BMAD**。

一句话：**最佳平替是 GitHub Spec Kit；最佳实践组合是 Spec Kit 管 spec/plan/tasks，Claude/Codex 原生能力管执行，AGENTS.md/CLAUDE.md 管工程规则，Hooks 管强制验证。**
