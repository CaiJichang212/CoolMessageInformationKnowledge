# 把Codex的Build-macOS-Apps插件迁移到Claude-Code

最近在整理 macOS 应用开发工作流时，我遇到一个很实用的问题：已经安装在 Codex 中的 **Build macOS Apps Plugin**，能不能迁移到其他编程助手或智能体工具中使用，比如 Claude Code、Trae 等？

答案是：可以，但不同工具的插件机制并不完全相同。本文先聚焦最常见的场景：**如何把 Build macOS Apps Plugin 安装到 Claude Code**。

我本地已有的插件目录如下：

```text
/Users/lzc/.codex/plugins/cache/openai-curated/build-macos-apps
```

目录结构大致如下：

```text
build-macos-apps % tree -L 3 .
```

## 安装思路

推荐采用 **Claude Code 的 skills-directory plugin（技能目录插件）** 方式安装，而不是直接修改 Codex 的 cache（缓存）目录。这样做更稳定，也方便后续维护和回滚。

Claude Code 会自动加载 `~/.claude/skills/` 下带 `.claude-plugin/plugin.json` 的目录，并以 `<name>@skills-dir` 的形式将其识别为 Plugin（插件）。安装到个人目录后，这个插件会在所有项目中可用。([Claude Code][1])

直接执行：

```bash
SRC="/Users/lzc/.codex/plugins/cache/openai-curated/build-macos-apps/c6ea566d"
DST="$HOME/.claude/skills/build-macos-apps"

rm -rf "$DST"
mkdir -p "$DST/.claude-plugin"

# 复制 Claude Code 可用的部分
rsync -a "$SRC/skills" "$DST/"
rsync -a "$SRC/commands" "$DST/" 2>/dev/null || true
rsync -a "$SRC/assets" "$DST/" 2>/dev/null || true
cp "$SRC/README.md" "$DST/" 2>/dev/null || true

# 创建 Claude Code plugin manifest（插件清单）
cat > "$DST/.claude-plugin/plugin.json" <<'JSON'
{
  "name": "build-macos-apps",
  "displayName": "Build macOS Apps",
  "version": "0.1.0",
  "description": "Build, debug, instrument, package, sign, notarize, and refactor macOS apps with SwiftUI and AppKit guidance.",
  "author": {
    "name": "OpenAI"
  }
}
JSON

# 检查结构
find "$DST" -maxdepth 3 -type f | sort
```

然后重启 Claude Code，或者在已打开的 Claude Code 里执行：

```text
/reload-plugins
```

Claude Code 的 Plugin（插件）里，Skill（技能）目录结构是 `skills/<skill-name>/SKILL.md`，调用时会带 namespace（命名空间），所以这些技能不是 `/build-run-debug`，而是类似下面这样：([Claude Code][2])

```text
/build-macos-apps:build-run-debug
/build-macos-apps:swiftui-patterns
/build-macos-apps:appkit-interop
/build-macos-apps:signing-entitlements
/build-macos-apps:packaging-notarization
/build-macos-apps:test-triage
```

你原目录里的 `commands/*.md` 也可以保留。Claude Code Plugin 支持 `commands/` 作为 flat Markdown commands（扁平 Markdown 命令），但官方建议新插件优先使用 `skills/`。([Claude Code][2]) 因此这几个也可能以 namespace 形式出现：

```text
/build-macos-apps:build-and-run-macos-app
/build-macos-apps:fix-codesign-error
/build-macos-apps:test-macos-app
```

验证安装：

```bash
claude plugin list
claude plugin details build-macos-apps@skills-dir
```

也可以进入 Claude Code 后运行：

```text
/plugin list
/help
```

注意两点。第一，不建议运行 `claude plugin install /Users/.../c6ea566d`，因为 `plugin install` 面向 marketplace（插件市场）安装；本地目录临时加载用 `--plugin-dir`，持久本地加载用上面的 `~/.claude/skills/<plugin>` 方式。([Claude API Docs][3]) 第二，暂时不要复制 `agents/openai.yaml`；Claude Code Plugin 的 agents（子代理）期望的是 Markdown frontmatter 格式，不是这个 OpenAI 插件里的 YAML 格式。([Claude Code][1])

临时测试版，不持久安装，也可以这样启动：

```bash
claude --plugin-dir "$HOME/.claude/skills/build-macos-apps"
```

`--plugin-dir` 只对当前 session（会话）生效；上面的 `~/.claude/skills/build-macos-apps` 方案则会在后续 Claude Code 会话中自动加载。([Claude API Docs][3])
